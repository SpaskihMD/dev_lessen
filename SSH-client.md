# 🐧 Полный конспект по SSH (Secure Shell) — с интерактивом и эмодзи

> 🔐 **SSH** — ваш ключ к удалённому управлению серверами.  
> ✅ Пройди чеклисты и выполни задания — и ты освоишь SSH на 100%!

---

## 📦 1. Установка SSH-сервера

```bash
sudo apt update && sudo apt install openssh-server -y
```

✅ **Чек-лист после установки:**  
- [ ] Нет ошибок в терминале  
- [ ] Пакет установлен (проверить: `dpkg -l | grep openssh-server`)

---

## 🎛️ 2. Управление службой (исправленные команды)

> ⚠️ **Важно:** `systemctl`, а НЕ `systemcts`!

```bash
sudo systemctl start ssh     # 🟢 Запустить
sudo systemctl enable ssh    # 🔄 Автозапуск при загрузке
sudo systemctl status ssh    # 📊 Статус (ищи "active (running)")
sudo systemctl stop ssh      # 🔴 Остановить
sudo systemctl restart ssh   # ♻️ Перезапуск после правки конфигов
sudo systemctl reload ssh    # 🔁 Перечитать конфиги без разрыва соединений
```

🧪 **Мини-задание:**  
Выполни `systemctl status ssh` и найди строку `Active: active (running)`.  
📸 Если нет — запусти сервер командой выше.

---

## 🌐 3. Узнать IP-адрес сервера

```bash
hostname -I          # Покажет IP (только цифры)
ip a                # Подробно о всех интерфейсах
curl ifconfig.me    # Внешний IP (если есть интернет)
```

📌 **Пример вывода:** `192.168.1.100`  
🔁 Сохрани этот IP — он понадобится для подключения.

---

## 🔌 4. Подключение к SSH-серверу

### 🐧 Linux / macOS / Windows (PowerShell)

```bash
ssh username@192.168.1.100
ssh -p 2222 username@192.168.1.100   # если порт не 22
```

### 🪟 Windows (PuTTY)

- Host: `192.168.1.100`  
- Port: `22`  
- Connection type: `SSH`

🧪 **Задание:**  
Подключись к серверу и выполни команду `whoami` — ты должен увидеть своё имя пользователя.

---

## 🗂️ 5. Важные файлы SSH

| 📁 Файл | 🧠 Назначение |
|---------|----------------|
| `/etc/ssh/sshd_config` | Конфиг **сервера** |
| `/etc/ssh/ssh_config` | Конфиг **клиента** |
| `~/.ssh/` | Твоя личная SSH-директория |
| `~/.ssh/authorized_keys` | Публичные ключи для входа без пароля |
| `~/.ssh/id_ed25519` (или `id_rsa`) | Твой **приватный** ключ (НИКОМУ не давай!) |
| `/var/log/auth.log` | Логи входов (Ubuntu/Debian) |

✅ **Чек-лист безопасности:**  
- [ ] Приватный ключ имеет права `600` (`chmod 600 ~/.ssh/id_*`)  
- [ ] Директория `~/.ssh/` имеет права `700`  
- [ ] Файл `authorized_keys` — `600`

---

## ⚙️ 6. Настройка сервера (`/etc/ssh/sshd_config`)

Открой файл:  
```bash
sudo nano /etc/ssh/sshd_config
```

🔧 **Рекомендуемые настройки (раскомментируй или добавь):**

```bash
Port 22                     # 🔐 Лучше сменить на 2222 (но не забудь потом указать -p)
PermitRootLogin no          # 🚫 Никогда не разрешай root по SSH
PasswordAuthentication yes  # 🤔 Временно. Потом замени на no, когда настроишь ключи
PubkeyAuthentication yes    # 🔑 Разрешаем вход по ключам
MaxAuthTries 3              # 🛡️ Защита от подбора
ClientAliveInterval 300     # ⏱️ Проверка каждые 5 минут
ClientAliveCountMax 2       # 🔌 Отключить после 2 пропущенных проверок
AllowUsers user1 user2      # 👥 Только эти пользователи могут входить
```

🧪 **Задание:**  
Измени порт на `2222`, перезапусти SSH и подключись снова с флагом `-p 2222`.

---

## 🔑 7. Вход по ключам (без пароля) — интерактивный гайд

### Шаг 1️⃣ — на **клиенте** (твой компьютер)

```bash
ssh-keygen -t ed25519 -C "мой_ключ_для_сервера"
```
📝 **Тебя спросят:**  
- Куда сохранить? (жми Enter — соглашайся с путём по умолчанию)  
- Пароль для ключа? (Enter = без пароля, но лучше задай)

### Шаг 2️⃣ — скопируй ключ на сервер

```bash
ssh-copy-id user@192.168.1.100
```
👉 Введи свой пароль от сервера (последний раз 😎)

### Шаг 3️⃣ — проверь, что работает

```bash
ssh user@192.168.1.100
```
🎉 **Если зашло без запроса пароля — ты молодец!**

🧪 **Бонус-задание:**  
Отключи вход по паролю (`PasswordAuthentication no`), перезапусти SSH и проверь, что только ключи работают.

## 🚇 8. Проброс портов (туннели)

### 🔹 Локальный проброс (с клиента на сервер)

```bash
ssh -L 8080:localhost:80 user@server
```
Теперь на своём компьютере открой `http://localhost:8080` — увидишь веб-сервер с удалённой машины.

### 🔹 Удалённый проброс (с сервера на клиент)

```bash
ssh -R 3000:localhost:3000 user@server
```
На сервере можно стучаться на `localhost:3000` и попадать на твой локальный сервер.

### 🔹 Динамический прокси (SOCKS5)

```bash
ssh -D 1080 user@server
```
Настрой браузер на `localhost:1080` (тип SOCKS5) — весь трафик пойдёт через сервер.

🧪 **Задание:**  
Сделай локальный проброс на порт 22 другого сервера внутри сети и подключись к нему.

## ⚡ 9. Полезные опции (шпаргалка)

| Опция | Что делает |
|-------|-------------|
| `-C` | Сжатие данных (медленные соединения) |
| `-f` | В фоновый режим (после ввода пароля) |
| `-N` | Не выполнять команды (только туннель) |
| `-v` / `-vvv` | Отладка подключения (где ошибка) |
| `-o ServerAliveInterval=60` | Держит соединение активным |

Пример:  
```bash
ssh -fN -L 8080:localhost:80 user@server   # фоновый туннель без shell
```

## 📝 10. Файл конфигурации клиента (`~/.ssh/config`)

Создай файл и забудь про длинные команды:

```bash
nano ~/.ssh/config
```

👇 **Пример содержимого:**

```bash
Host myvps
    HostName 203.0.113.5
    User admin
    Port 2222
    IdentityFile ~/.ssh/id_ed25519

Host home
    HostName home.ddns.net
    User pi
    ProxyJump user@bastion
```

✅ **Теперь подключение — одной командой:**  
```bash
ssh myvps
```

🧪 **Задание:**  
Создай алиас `myserver` для своего сервера и подключись через него.

## 🔐 11. Безопасность — обязательные пункты

### ✅ Обязательно сделать:

```bash
# 1. Запретить вход root
PermitRootLogin no

# 2. Использовать ключи, отключить пароли (когда готов)
PasswordAuthentication no

# 3. Сменить порт с 22 (уменьшит количество ботов)
Port 54321

# 4. Поставить fail2ban (бан автоматически)
sudo apt install fail2ban -y
sudo systemctl enable fail2ban
```

## 🩺 12. Диагностика проблем (интерактивный алгоритм)

```
❌ Не подключается?
│
├─ 1. ping <IP>          → если не пингуется → проблема с сетью
│
├─ 2. telnet <IP> 22     → если нет ответа → фаервол или SSH не слушает
│
├─ 3. ssh -vvv user@IP   → читай последние 5 строк вывода
│
├─ 4. Проверь на сервере:
│   • sudo systemctl status ssh
│   • sudo netstat -tlnp | grep :22
│   • sudo ufw status
│
└─ 5. Смотри логи:
    sudo journalctl -u ssh -n 30
    sudo tail -f /var/log/auth.log
```

## 🧠 13. Типовые ошибки и их решение

| Ошибка | 🛠️ Решение |
|--------|-------------|
| `Connection refused` | Сервер не запущен или порт не 22 (`systemctl status ssh`) |
| `Permission denied (publickey,password)` | Неверный логин/пароль или отключён вход по паролю |
| `Host key verification failed` | Изменился ключ сервера → удали строку из `~/.ssh/known_hosts` |
| `Connection timed out` | Фаервол или неверный IP |
| `Too many authentication failures` | Перезайди или подожди, очисти кеш ключей |

## 📚 Шпаргалка на один лист

```bash
# Установка и запуск
sudo apt install openssh-server -y && sudo systemctl enable --now ssh

# Статус и IP
sudo systemctl status ssh | head -5 && hostname -I

# Ключи
ssh-keygen -t ed25519
ssh-copy-id user@IP

# Подключение
ssh user@IP -p 2222 -i ~/.ssh/id_ed25519

# Туннель (локальный)
ssh -L 8080:localhost:80 user@IP

# Копирование файлов
scp file.txt user@IP:~/  
scp user@IP:~/file.txt .

# Логи
journalctl -u ssh -f
```
