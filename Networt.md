# 🧠 Шпаргалка: Команды для диагностики и мониторинга сетей

> Подходит для Linux, macOS, WSL. Для Windows есть отдельный блок.

---

## 🌐 1. Просмотр и настройка сетевых интерфейсов

| Команда | Описание |
| :--- | :--- |
| `ip a` или `ip addr` | Показать все сетевые интерфейсы, IP-адреса, MAC-адреса и состояние |
| `ifconfig` | Классический просмотр интерфейсов (может отсутствовать в новых дистрибутивах) |
| `ip link set eth0 up` | Включить сетевой интерфейс eth0 |
| `ip link set eth0 down` | Выключить сетевой интерфейс eth0 |
| `ip route` | Показать таблицу маршрутизации (куда отправляются пакеты) |
| `route -n` | Показать таблицу маршрутизации в числовом формате (без DNS-имён) |
| `ip neigh` | Показать ARP-таблицу (соответствие IP и MAC адресов) |
| `arp -a` | Альтернативный способ просмотра ARP-таблицы |

---

## 📡 2. Проверка соединения

| Команда | Описание |
| :--- | :--- |
| `ping ya.ru` | Проверить доступность удалённого хоста (бесконечная отправка пакетов) |
| `ping -c 4 8.8.8.8` | Отправить ровно 4 пакета и остановиться |
| `ping -i 0.5 google.com` | Отправлять пакеты каждые 0.5 секунды |
| `traceroute google.com` | Отследить маршрут пакета до узла (каждый прыжок между роутерами) |
| `tracepath google.com` | Упрощённая версия traceroute (не требует прав root) |
| `mtr ya.ru` | Комбинация ping + traceroute в реальном времени (очень удобно) |
| `pathping ya.ru` | Windows-версия: показывает потери пакетов на каждом маршрутизаторе |

---

## 🔌 3. Просмотр портов и соединений

| Команда | Описание |
| :--- | :--- |
| `ss -tulpn` | Показать все слушающие TCP и UDP порты с информацией о процессах |
| `netstat -tulpn` | Классическая утилита (аналог ss, но старше) |
| `ss -tunap` | Показать все текущие соединения (установленные и ожидающие) |
| `lsof -i :80` | Найти процесс, который использует порт 80 |
| `lsof -i` | Показать все открытые сетевые соединения с именами процессов |
| `sockstat -4` | (macOS/BSD) Показать все IPv4 сокеты и владеющих ими процессов |

---

## 📂 4. Работа с DNS

| Команда | Описание |
| :--- | :--- |
| `dig ya.ru` | Получить A-запись (IP по домену), TTL, NS-сервера и другую информацию |
| `dig -x 8.8.8.8` | Обратный запрос: узнать доменное имя по IP-адресу |
| `nslookup ya.ru` | Простой опрос DNS-сервера (удобно для быстрой проверки) |
| `host google.com` | Максимально короткий ответ: IP-адрес по домену |
| `resolvectl status` | (Systemd Linux) Посмотреть какой DNS-сервер используется сейчас |
| `systemd-resolve --status` | Устаревший аналог resolvectl status |

## 🔥 5. Мониторинг трафика в реальном времени

| Команда | Описание |
| :--- | :--- |
| `iftop` | Интерактивный мониторинг: показывает TOP-5 хостов и скорость передачи |
| `nethogs` | Показывает скорость интернета в разрезе процессов (браузер, игра и т.д.) |
| `bmon` | Псевдографический монитор загрузки канала с красивым интерфейсом |
| `vnstat` | Статистика трафика за сутки, неделю, месяц (работает в фоновом режиме) |
| `ip -s link show eth0` | Показать статистику ошибок и потерянных пакетов для интерфейса eth0 |
| `nload` | Простой график входящего и исходящего трафика |

## 🛠️ 6. Диагностика сокетов и сканирование

| Команда | Описание |
| :--- | :--- |
| `telnet example.com 80` | Вручную отправить запрос к серверу (проверить открыт ли TCP порт) |
| `nc -zv google.com 443` | Netcat в режиме сканера: проверить открыт ли порт без отправки данных |
| `nmap -sS -p 1-1000 192.168.1.1` | Сканер портов (осторожно — может считаться атакой!) |
| `nmap -sn 192.168.1.0/24` | Найти все живые устройства в локальной сети |
| `curl -I ya.ru` | Получить только HTTP-заголовки (проверка работы веб-сервера) |
| `curl -v ya.ru` | Подробный вывод: весь процесс подключения и обмена данными |

## 🪟 7. Команды для Windows (CMD или PowerShell)

| Команда | Описание |
| :--- | :--- |
| `ipconfig /all` | Показать ВСЮ информацию о сетевых адаптерах (IP, MAC, DNS, DHCP) |
| `ipconfig /displaydns` | Посмотреть содержимое кеша DNS |
| `ipconfig /flushdns` | Очистить кеш DNS (когда сайт открывается по старому IP) |
| `ipconfig /release` | Освободить текущий IP-адрес (для DHCP) |
| `ipconfig /renew` | Запросить новый IP-адрес у DHCP-сервера |
| `tracert -d ya.ru` | Трассировка без разрешения имён (работает намного быстрее) |
| `Get-NetTCPConnection` | (PowerShell) Показать список всех TCP-соединений |
| `Test-NetConnection google.com -Port 443` | (PowerShell) Проверить доступность порта 443 на удалённом сервере |

## ⚡ 8. Продвинутые и редкие команды

| Команда | Описание |
| :--- | :--- |
| `ip monitor` | Следить за изменениями маршрутов и интерфейсов в реальном времени |
| `ss -to` | Показать таймеры TCP (полезно для отладки зависших соединений) |
| `arping 192.168.1.1` | Узнать MAC-адрес соседнего устройства (даже если обычный ping запрещён) |
| `tcpdump -i eth0 -c 10` | Захватить 10 пакетов с интерфейса для анализа |
| `ethtool eth0` | Показать параметры железной сетевой карты (скорость, дуплекс, автодоговор) |
| `whois ya.ru` | Получить информацию о владельце домена |
| `iperf3 -c 192.168.1.10` | Измерить реальную пропускную способность до другого компьютера |

## 🧭 Алгоритм диагностики сети (быстрая инструкция)

| Шаг | Команда | Что проверяем |
| :--- | :--- | :--- |
| 1 | `ip link` | Поднят ли сетевой интерфейс? |
| 2 | `ping 192.168.1.1` | Есть ли связь с соседним устройством (например, роутером)? |
| 3 | `ip route` | Есть ли маршрут по умолчанию (default gateway)? |
| 4 | `ping 8.8.8.8` | Есть ли выход в интернет (по IP)? |
| 5 | `dig ya.ru` | Правильно ли работает DNS (преобразует имя в IP)? |
| 6 | `ss -tulpn \| grep 80` | Слушает ли нужный порт ваш сервер? |

---

## 💡 Золотые правила диагностики

> Если ping до IP адреса проходит, а до сайта — нет → проблема в DNS.

> Если ping до шлюза есть, а до 8.8.8.8 нет → проверьте маршруты (`ip route`).

> Если тормозят игры или видео → запустите `mtr` и найдите, на каком узле потери пакетов.

> Если порт 80 закрыт, а веб-сервер не открывается → `lsof -i :80` покажет, кто его заблокировал.

> Если после настройки сети ничего не работает → `ipconfig /flushdns` (Windows) или перезапустить NetworkManager (Linux).
