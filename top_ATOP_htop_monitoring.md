# ⚙️ Контроль нагрузки и процессов в Linux: top, htop, atop

Мониторинг процессов — основа диагностики проблем с производительностью. Эти три утилиты позволяют видеть, кто и сколько потребляет ресурсов, и при необходимости "усмирять" проблемные процессы. У каждой свои сильные стороны, и вместе они покрывают почти все сценарии — от быстрой диагностики до анализа периодических проблем.

## 📊 Сравнительная таблица

| Характеристика | `top` | `htop` | `atop` |
|---|---|---|---|
| **Главная особенность** | Есть везде "из коробки" | Красивый интерфейс, управление мышью | Ведёт историю, можно "отмотать" время |
| **Установка** | Предустановлена во всех дистрибутивах | Нужно ставить (`apt install htop`) | Нужно ставить (`apt install atop`) |
| **Управление** | Только клавиатура, команды надо помнить | Клавиатура + мышь, подсказки внизу | Клавиатура, много специфичных режимов |
| **История** | ❌ Только текущий момент | ❌ Только текущий момент | ✅ Логи за дни и недели |
| **Детализация** | CPU, память, процессы | CPU, память, диски, сеть (расширенно) | CPU, память, диски, сеть, GPU — максимально подробно |
| **Для кого** | Быстрый взгляд, минимальные системы | Повседневная работа, новички | Глубокий анализ, поиск периодических проблем |

## 📟 1. top — классика, которая есть везде

`top` — стандартный инструмент для мониторинга в реальном времени. Она есть в любом Linux, что делает её первой линией обороны при проблемах.

### Запуск
```bash
top
```

### Что мы видим: две информационные зоны

**Верхняя часть — системная статистика:**

```
top - 14:30:22 up 10 days,  3:15,  2 users,  load average: 0.08, 0.03, 0.01
Tasks: 112 total,   1 running, 111 sleeping,   0 stopped,   0 zombie
%Cpu(s):  2.3 us,  1.2 sy,  0.0 ni, 96.5 id,  0.0 wa,  0.0 hi,  0.0 si,  0.0 st
KiB Mem :  2045960 total,   450312 free,  1021456 used,   574192 buff/cache
KiB Swap:  1048572 total,  1048572 free,        0 used.   856240 avail Mem
```

| Поле | Что означает | На что смотреть |
|------|--------------|----------------|
| **load average** | Средняя нагрузка за 1, 5, 15 минут | Если > количества ядер CPU — перегруз |
| **Tasks** | Общее число процессов, сколько работает, спит, "зомби" | `zombie` > 0 — проблемы с процессами-сиротами |
| **us** (user) | Время CPU на пользовательские процессы | Высокое значение — код приложения нагружает |
| **sy** (system) | Время CPU на задачи ядра | Высокое значение — проблема с драйверами или системой |
| **id** (idle) | Простой CPU | Маленькое значение — ресурс выжат под завязку |
| **wa** (iowait) | Ожидание дисковых операций | > 5-10% — диск не успевает |
| **Mem/Swap** | Использование оперативной памяти и свопа | Swap used > 0 — не хватает RAM |

**Нижняя часть — таблица процессов:**

| Столбец | Расшифровка |
|---------|-------------|
| `PID` | Идентификатор процесса |
| `USER` | Владелец |
| `PR` / `NI` | Приоритет (чем меньше число, тем выше приоритет) |
| `VIRT` | Виртуальная память (сколько процесс "попросил") |
| `RES` | Реальная память (сколько на самом деле занято) |
| `SHR` | Разделяемая память |
| `S` | Состояние (R — работает, S — спит, Z — зомби) |
| `%CPU` | Процент использования процессора |
| `%MEM` | Процент использования памяти |
| `TIME+` | Общее время работы |
| `COMMAND` | Имя процесса |

### Горячие клавиши в top

| Клавиша | Действие |
|---------|----------------------------------|
| `M` | Сортировка по использованию **памяти** (самые "жирные" сверху) |
| `P` | Сортировка по **CPU** (по умолчанию) |
| `T` | Сортировка по **времени работы** |
| `N` | Сортировка по **PID** |
| `u` | Показать процессы **конкретного пользователя** (спросит имя) |
| `k` | **Убить процесс** — спросит PID и сигнал (15 — мягко, 9 — жёстко) |
| `r` | Изменить приоритет (renice) |
| `f` | Выбрать, какие столбцы отображать |
| `o` | Изменить порядок столбцов |
| `I` | Переключить режим отображения CPU (Irix/Solaris) |
| `c` | Показать полный путь к команде вместо имени |
| `q` | Выйти |

### Полезные команды запуска

```bash
top -u username          # сразу фильтровать по пользователю
top -p 1234              # следить только за процессом с PID 1234
top -d 1                 # обновлять каждую секунду
top -b -n 1 > stats.txt  # сохранить один снимок в файл (batch mode)
```

## 🎨 2. htop — top, только удобнее и красивее

`htop` — это современная альтернатива `top` с цветным интерфейсом, поддержкой мыши и кучей удобств.

### Установка
```bash
# Ubuntu / Debian
sudo apt install htop

# CentOS / RHEL
sudo dnf install htop
```

### Запуск
```bash
htop
```

### Особенности интерфейса

- **Вверху** — цветные графики загрузки каждого ядра CPU, памяти и swap
- **Слева сверху** — информация о процессах, load average, аптайм
- **Основная область** — список процессов с возможностью горизонтальной прокрутки (в `top` такого нет)
- **Снизу** — подсказки по горячим клавишам (F1-F10)

### Горячие клавиши (и клики мышью!)

| Клавиша | Что делает |
|---------|-------------------------------------|
| `F1` / `h` | Справка |
| `F2` | **Настройки** — можно добавить/убрать столбцы, изменить цвета, настроить метрики |
| `F3` / `/` | **Поиск** процесса по имени |
| `F4` | **Фильтр** — оставить только процессы, содержащие в имени заданную строку |
| `F5` / `t` | **Дерево процессов** — показать иерархию (родители-дети) |
| `F6` | Выбрать столбец для **сортировки** |
| `F7` / `F8` | Повысить / понизить **приоритет** (nice) |
| `F9` / `k` | **Убить процесс** (откроется меню сигналов) |
| `F10` / `q` | Выход |
| `Space` | Отметить процесс (для групповых операций) |
| `u` | Показать процессы конкретного пользователя |
| `M` | Сортировка по памяти (как в top) |
| `P` | Сортировка по CPU |
| `T` | Сортировка по времени |
| `H` | Скрыть/показать потоки (threads) — по умолчанию htop показывает и процессы, и потоки |
| `K` | Скрыть/показать потоки ядра |
| `\` | Снять все фильтры |

### Управление мышью

- Клик на заголовок столбца — сортировка по этому столбцу
- Клик на процесс — выделение
- Двойной клик — ничего не делает, но это красиво

### Полезные опции запуска

```bash
htop -u username        # показать процессы пользователя
htop -p PID1,PID2       # показать только указанные PID
htop -t                 # сразу в режиме дерева
htop -C                 # монохромный режим (без цветов)
htop -d 10              # обновление каждую секунду (в десятых долях)
```

### Настройка htop (F2)

В настройках можно:
- Добавить/убрать метрики в верхней панели (CPU, память, сеть, диски)
- Настроить отображаемые столбцы (например, добавить PPID, IO, пользователя)
- Выбрать цветовую схему
- Сохранить настройки (они пишутся в `~/.config/htop/htoprc`)

## 📜 3. atop — мониторинг с историей (самый мощный)

Главная фишка `atop` в том, что он **по умолчанию ведёт логи**. Если сервер "притормаживал" час назад, вы можете открыть лог и увидеть, какой процесс был виноват. Для периодических проблем это незаменимо.

### Установка и настройка

```bash
# Ubuntu / Debian
sudo apt install atop -y

# CentOS / RHEL
sudo dnf install atop -y

# Включить сервис для автоматического сбора логов
sudo systemctl enable atop --now
```

### Запуск (режимы)

```bash
atop                 # интерактивный режим (как top, но с другим интерфейсом)
atop -r              # открыть сегодняшний лог
atop -r /var/log/atop/atop_20250227  # открыть лог за конкретный день
```

### Что мы видим в atop

**Верхняя часть** — системные метрики, разбитые по категориям:

- `PRC` — процессы (всего, запущено, зомби, клонировано)
- `CPU` — загрузка процессора (sys, user, irq, idle, wait, steal)
- `CPL` — load average, переключения контекста, прерывания
- `MEM` — память (total, free, cached, buffered, swap)
- `DSK` — диски (чтение/запись в МБ/с, процент загрузки)
- `NET` — сетевые интерфейсы
- `GPU` — если есть видеокарта

**Нижняя часть** — процессы с детализацией:

| Столбец | Значение |
|---------|----------|
| `PID` | ID процесса |
| `SYSCPU` | Время CPU в ядре |
| `USRCPU` | Время CPU в пользовательском режиме |
| `RDELAY` | Время ожидания ресурсов (CPU, память) |
| `VGROW` / `RGROW` | Рост виртуальной / реальной памяти |
| `RDDSK` / `WRDSK` | Чтение / запись на диск |
| `RNET` / `SNET` | Приём / передача по сети |
| `MEM` | Использование памяти |
| `CMD` | Команда |

### Управление в интерактивном режиме

| Клавиша | Действие |
|---------|----------------------------------|
| `g` | Общий вид (по умолчанию) |
| `m` | **Детали по памяти** |
| `d` | **Детали по дискам** (показать, сколько каждый процесс читает/пишет) |
| `n` | **Детали по сети** |
| `c` | Показать полную командную строку |
| `v` | Разная информация (PPID, пользователь, статус) |
| `C` | Сортировка по **CPU** (Shift + C) |
| `M` | Сортировка по **памяти** (Shift + M) |
| `D` | Сортировка по **диску** (Shift + D) |
| `N` | Сортировка по **сети** (Shift + N) |
| `u` | Сводка по **пользователям** (сколько ресурсов кто потребляет) |
| `p` | Сводка по **программам** (одинаковые имена процессов суммируются) |
| `q` | Выход |

### Работа с логами (самое ценное!)

При просмотре лога (`atop -r`) появляются дополнительные команды:

| Клавиша | Действие |
|---------|----------|
| `t` | Перейти **вперёд** по времени (к следующему снимку) |
| `Shift + t` | Перейти **назад** по времени |
| `b` / `g` | Перейти в конец / начало лога |
| `T` | Перейти к конкретному времени |

### Настройка частоты сбора

По умолчанию atop делает снимки каждые 10 минут. Для более детального анализа можно уменьшить интервал:

```bash
# Редактируем конфиг (Ubuntu/Debian)
sudo nano /etc/default/atop

# Меняем параметр (в секундах)
INTERVAL=60   # теперь снимок каждую минуту

# Перезапускаем сервис
sudo systemctl restart atop
```

## 🧠 Какой инструмент когда использовать

### Сценарий 1. "Сервер стал тормозить прямо сейчас, быстро посмотреть"

👉 **`top`**

Зашли, посмотрели load average, увидели процесс с высоким %CPU или %MEM, нажали `k`, ввели PID — проблема решена.

### Сценарий 2. "Хочу красиво и удобно следить за системой в реальном времени"

👉 **`htop`**

Установили, запустили, мышкой отсортировали по памяти, нашли виновника, нажали F9 — убили. И всё это с цветными графиками и подсказками.

### Сценарий 3. "Сервер притормаживал ночью, сейчас всё нормально, но надо найти причину"

👉 **`atop`**

Открыли лог за вчера (`atop -r /var/log/atop/atop_20250315`), клавишами `t` дошли до проблемного времени, увидели, какой процесс разгулялся.

### Сценарий 4. "Не могу понять, CPU или диск виноваты"

👉 **`atop`**

В верхней части сразу видно `CPU` (загрузка процессора) и `DSK` (загрузка дисков). А если нажать `d`, то увидите, какой именно процесс больше всех пишет на диск.

### Сценарий 5. "Процесс есть, но я не знаю, что это за программа"

👉 **`htop`** или **`atop`**

В `htop` нажмите `c` или просто посмотрите на столбец Command — будет виден полный путь. В `atop` нажмите `c` для полной командной строки.

## 📋 Шпаргалка по сортировке и поиску

| Действие | top | htop | atop |
|----------|-----|------|------|
| **Сортировка по CPU** | `P` | Клик на столбец `CPU%` или `P` | `Shift + C` |
| **Сортировка по памяти** | `M` | Клик на `MEM%` или `M` | `Shift + M` |
| **Сортировка по диску** | нет | нет (только I/O) | `Shift + D` |
| **Сортировка по сети** | нет | нет | `Shift + N` |
| **Поиск процесса** | `L` (искать) + `&` | `F3` или `/` | `/` |
| **Фильтр по имени** | `O` (сложно) | `F4` | нет |
| **Только пользователь** | `u` | `u` | `u` (сводка) |

## ⚙️ Дополнительные советы

### kill — завершение процессов

Если процесс не отвечает, можно отправить ему сигнал. Самые полезные:

```bash
kill -15 PID    # SIGTERM — мягкое завершение (процесс может успеть сохранить данные)
kill -9 PID     # SIGKILL — жёсткое убийство (мгновенно, без шансов на сохранение)
```

В `top` и `htop` можно убить процесс прямо из интерфейса (клавиша `k` в top, `F9` в htop).

### nice и renice — управление приоритетом

Приоритет процесса (nice) может быть от -20 (высший приоритет) до 19 (низший). Чем **меньше** число, тем **выше** приоритет.

```bash
nice -n 10 ./script.sh    # запустить скрипт с пониженным приоритетом
renice -n 5 -p 1234       # изменить приоритет уже запущенного процесса
```

В `htop` можно менять приоритет клавишами `F7` (увеличить приоритет, уменьшить nice) и `F8` (уменьшить приоритет, увеличить nice).

### strace и lsof — если нужно копнуть глубже

В `htop` есть удобные "шорткаты" для дополнительных инструментов:

- Нажмите `s` — откроется `strace` для выбранного процесса (показывает, какие системные вызовы он делает)
- Нажмите `l` — откроется `lsof` (показывает, какие файлы и сокеты открыты)
