# 📚 Git шпаргалка — основные команды для терминала

## ⚙️ Настройка Git

```bash
git config --global user.name "Ваше Имя"          # 👤 Установить имя пользователя
git config --global user.email "email@example.com" # 📧 Установить email
git config --global core.editor "code --wait"     # ✏️ Установить редактор (VS Code)
git config --global credential.helper store       # 🔐 Сохранить пароль (не спрашивать каждый раз)
git config --global credential.helper 'cache --timeout=3600' # ⏱️ Кэшировать пароль на 1 час
git config --list                                 # 📋 Показать все настройки
```

## 🆕 Создание репозитория

```bash
git init                                          # 🏗️ Создать новый локальный репозиторий
git clone https://github.com/пользователь/репо.git # 📥 Склонировать удалённый репозиторий
git clone --depth 1 <url>                         # ⚡ Клонировать только последний коммит (легковесный)
```

## 📍 Работа с изменениями (файлы)

```bash
git status                                        # 📊 Показать состояние файлов (изменённые, новые, удалённые)
git add <файл>                                    # ➕ Добавить файл в индекс (подготовить к коммиту)
git add .                                         # 📂 Добавить все файлы в текущей папке
git add -A                                        # 🧹 Добавить все файлы (включая удалённые)
git rm <файл>                                     # ❌ Удалить файл из репозитория и рабочей папки
git rm --cached <файл>                            # 🗑️ Удалить файл из индекса, но оставить в рабочей папке (перестать отслеживать)
git mv <старое> <новое>                           # 📝 Переименовать или переместить файл
git restore <файл>                                # ↩️ Отменить изменения в файле (неподготовленные)
git restore --staged <файл>                       # ⏪ Убрать файл из индекса (но изменения сохранить)
git reset HEAD <файл>                             # 🔄 (старый способ) Убрать из индекса, но изменения сохранить
```

## 💾 Коммиты (сохранение изменений)

```bash
git commit -m "Сообщение"                         # 💾 Создать коммит с сообщением
git commit -a -m "Сообщение"                      # 🚀 Добавить все отслеживаемые файлы и сразу сделать коммит (пропуская git add)
git commit --amend -m "Новое сообщение"           # 🔁 Изменить последний коммит (сообщение или файлы)
git commit --amend --no-edit                       # ✨ Добавить изменения в последний коммит, не меняя сообщение
```

## 📜 История коммитов

```bash
git log                                           # 📜 Показать всю историю коммитов
git log --oneline                                 # 🧵 Показать историю в сокращённом виде (одна строка на коммит)
git log --graph --oneline --all                   # 🌲 Показать историю в виде графа с ветками
git log -p                                        # 🔍 Показать историю с изменениями в файлах
git show <хэш_коммита>                            # 🔎 Показать изменения в конкретном коммите
git diff                                          # ➖➕ Показать неподготовленные изменения (до git add)
git diff --staged                                 # 🎭 Показать подготовленные изменения (после git add, до коммита)
git diff <хэш1> <хэш2>                            # 🔄 Сравнить два коммита
```

## 🌿 Ветки (branch)

```bash
git branch                                        # 🌿 Показать список локальных веток
git branch -r                                     # 🌍 Показать удалённые ветки
git branch -a                                     # 🗺️ Показать все ветки (локальные + удалённые)
git branch <имя_ветки>                            # ✨ Создать новую ветку
git checkout <имя_ветки>                          # 🔀 Переключиться на другую ветку
git checkout -b <имя_ветки>                       # 🌱 Создать ветку и сразу переключиться на неё
git switch <имя_ветки>                            # 🔀 (новый способ) Переключиться на ветку
git switch -c <имя_ветки>                         # 🌱 (новый способ) Создать и переключиться
git branch -d <имя_ветки>                         # ❌ Удалить локальную ветку (объединённую)
git branch -D <имя_ветки>                         # 💣 Принудительно удалить ветку (даже если не объединена)
git branch -m <новое_имя>                         # ✏️ Переименовать текущую ветку
git merge <имя_ветки>                             # 🔗 Слить ветку с текущей
git merge --abort                                 # 🛑 Отменить слияние при конфликте
```

## 🌍 Удалённые репозитории (remote)

```bash
git remote -v                                     # 📋 Показать удалённые репозитории (url)
git remote add origin https://github.com/user/repo.git # 🔗 Добавить удалённый репозиторий с именем origin
git remote remove origin                          # 🔌 Удалить связь с удалённым репозиторием
git remote rename origin upstream                 # ✏️ Переименовать remote
```

## ⬇️⬆️ Синхронизация (pull / push)

```bash
git pull                                          # ⬇️ Скачать изменения с сервера и сразу слить (pull = fetch + merge)
git pull --rebase                                 # 🎢 Скачать изменения и применить свои коммиты поверх (чище история)
git fetch                                         # 📡 Скачать изменения с сервера НЕ сливая их (только информация)
git fetch --prune                                 # 🧹 Скачать изменения и удалить локальные ссылки на удалённые ветки, которых больше нет
git push                                          # 📤 Отправить коммиты в удалённый репозиторий
git push -u origin main                           # 🚀 Отправить и установить upstream (связать ветки для будущих push/pull)
git push --force                                  # 💥 Принудительно отправить (опасно! перезаписывает историю)
git push --force-with-lease                      � # 🛡️ Безопасный force push (не перезапишет чужие изменения)
git push origin --delete <ветка>                  # 🗑️ Удалить ветку на удалённом репозитории
```

## 🔄 Отмена изменений (reset / revert)

```bash
git reset --soft HEAD~1                           # 🧠 Отменить последний коммит, но оставить изменения в индексе (готовыми к коммиту)
git reset --mixed HEAD~1                          # 📦 Отменить последний коммит, изменения оставить в рабочей папке (по умолчанию)
git reset --hard HEAD~1                           # ☠️ Полностью удалить последний коммит и изменения (НЕВОЗВРАТИМО для незакоммиченных данных!)
git reset --hard <хэш>                            # ⏱️ Откатить состояние репозитория к определённому коммиту (потеря всего после)
git revert <хэш>                                  # 🔄 Создать НОВЫЙ коммит, отменяющий изменения указанного (безопасно для истории)
git revert HEAD                                   # 🚫 Отменить последний коммит новым коммитом
```

## 💡 Полезные команды

```bash
git stash                                         # 📥 Временно спрятать незакоммиченные изменения (например, перед переключением ветки)
git stash list                                    # 📋 Показать список сохранённых stash
git stash apply                                   # 📤 Применить последний stash (но оставить его в списке)
git stash pop                                     # 🍿 Применить последний stash и удалить его из списка
git stash drop                                    # 🗑️ Удалить последний stash
git stash clear                                   # 🧹 Удалить ВСЕ stash
git tag                                           # 🏷️ Показать все теги
git tag v1.0                                      # 🏷️ Создать лёгкий тег на текущем коммите
git tag -a v1.0 -m "Описание"                     # 📝 Создать аннотированный тег с описанием
git push origin --tags                            # 📤 Отправить теги на сервер
git grep "что_искать"                             # 🔍 Искать текст по всем файлам в репозитории
git blame <файл>                                  # 🕵️ Показать, кто и когда изменил каждую строку файла
git reflog                                        # 🧠 Показать историю перемещений HEAD (можно найти "потерянные" коммиты)
git clean -fd                                     # 🧹 Удалить все НЕОТСЛЕЖИВАЕМЫЕ файлы и папки (осторожно!)
```

## ⚠️ Частые сценарии

```bash
# 🔄 Обновить свой локальный main без потери изменений
git checkout main
git pull --rebase origin main

# 🧹 Убрать файл из последнего коммита (но оставить изменения)
git reset --soft HEAD~1
git restore --staged <файл>
git commit -m "Новый коммит без файла"

# 🔁 Слить изменения из main в текущую ветку
git fetch origin
git merge origin/main

# 🚑 Отменить все незакоммиченные изменения в папке (опасно!)
git restore .
# или
git reset --hard HEAD

# ✨ Перебазировать ветку поверх main (чистая линейная история)
git checkout feature
git rebase main
```

## 📖 Терминология (коротко)

| Термин | Значение |
|--------|----------|
| 🧺 **Working Directory** | Рабочая папка с файлами |
| 📦 **Staging Area / Index** | Промежуточная область (перед коммитом) |
| 💾 **Commit** | Снимок состояния файлов с сообщением |
| 🌿 **Branch** | Отдельная линия разработки |
| 🔗 **Merge** | Слияние двух веток |
| 🎢 **Rebase** | Перенос коммитов на другую основу (линейная история) |
| 🌍 **Remote** | Удалённый репозиторий (например на GitHub) |
| 🧠 **HEAD** | Указатель на текущий коммит / ветку |

> 💬 **Совет:** Команда `git help <команда>` показывает подробную документацию прямо в терминале. Например: `git help commit`

🎉 **Git — это мощно и не так страшно, когда знаешь основные команды!**
